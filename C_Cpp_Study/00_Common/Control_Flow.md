# Control Flow

> **학습 목표**
>
> C와 C++에서 프로그램의 실행 흐름을 제어하는 조건문과 반복문을
> 이해한다. 단순히 `if`, `for`, `while` 문법을 암기하는 것이 아니라
> **조건식 → 분기 → 반복 → 상태 변화 → 종료 조건 → 알고리즘 → 임베디드
> 제어 흐름**으로 연결해서 이해한다.
>
> 이 노트는 `C_Cpp_Study/00_Common/Control_Flow.md`에 위치하며
> `Data_Type.md`, `Operator.md` 다음 단계로 학습한다.

------------------------------------------------------------------------

## 1. 제어 흐름이란?

### 한 문장 정의

**제어 흐름(Control Flow)은 프로그램의 명령문이 어떤 순서와 조건에 따라
실행되는지를 결정하는 흐름이다.**

기본적으로 프로그램은 위에서 아래로 순차 실행된다.

``` c
int a = 10;
int b = 20;
int sum = a + b;
```

``` mermaid
flowchart TD
    A["a = 10"] --> B["b = 20"]
    B --> C["sum = a + b"]
```

하지만 실제 프로그램에서는 다음과 같은 판단이 필요하다.

``` text
온도가 너무 높은가?
사용자가 버튼을 눌렀는가?
입력값이 정상인가?
반복 작업이 끝났는가?
UART 데이터가 도착했는가?
```

이때 제어문을 사용한다.

## 2. 제어 흐름의 전체 구조

``` mermaid
mindmap
```

``` mermaid

    B --> C["분기"]
    C --> D["반복"]
    D --> E["종료"]
```

# 3. 조건식

조건문을 이해하려면 먼저 **조건식(condition expression)**을 이해해야
한다.

예:

``` c
age >= 20
```

``` c
score == 100
```

``` c
temperature > 80
```

``` c
age >= 20 && age <= 30
```

`Operator.md`에서 배운 비교 연산자와 논리 연산자가 조건식을 만드는
핵심이다.

``` mermaid
flowchart LR
    A["Data"] --> B["비교 / 논리 연산"]
    B --> C["조건식"]
    C --> D["참 / 거짓 판단"]
    D --> E["Control Flow"]
```

# 4. `if`

`if`는 조건이 참일 때 특정 코드를 실행한다.

기본 구조:

``` c
if (condition)
{
    /* condition이 참일 때 실행 */
}
```

예:

``` c
int temperature = 90;

if (temperature >= 80)
{
    printf("High temperature\n");
}
```

동작:

``` mermaid
flowchart TD
    A["temperature >= 80"] --> B{"조건이 참인가?"}
    B -->|"Yes"| C["High temperature 출력"]
    B -->|"No"| D["if 블록 건너뜀"]
    C --> E["다음 코드"]
    D --> E
```

------------------------------------------------------------------------

## 4.1 중괄호 `{}`

조건문 내부의 여러 문장을 하나의 블록으로 묶는다.

``` c
if (temperature >= 80)
{
    printf("Warning\n");
    printf("High temperature\n");
}
```

문장이 하나일 때 중괄호를 생략할 수 있는 경우도 있지만 학습 초기에는
가능한 한 명시적으로 작성한다.

``` c
if (temperature >= 80)
{
    printf("Warning\n");
}
```

> \[!TIP\] 중괄호를 일관되게 사용하면 코드 수정 과정에서 발생하는 실수를
> 줄이고 실행 범위를 쉽게 확인할 수 있다.

------------------------------------------------------------------------

# 5. `if - else`

조건이 참일 때와 거짓일 때 서로 다른 코드를 실행한다.

``` c
if (condition)
{
    /* true */
}
else
{
    /* false */
}
```

예:

``` c
int number = 10;

if (number % 2 == 0)
{
    printf("Even\n");
}
else
{
    printf("Odd\n");
}
```

``` mermaid
flowchart TD
    A["number % 2 == 0"] --> B{"짝수인가?"}
    B -->|"Yes"| C["Even"]
    B -->|"No"| D["Odd"]
    C --> E["다음 코드"]
    D --> E
```

------------------------------------------------------------------------

# 6. `else if`

조건이 여러 개인 경우 사용한다.

``` c
if (condition1)
{
    /* ... */
}
else if (condition2)
{
    /* ... */
}
else
{
    /* ... */
}
```

예:

``` c
int score = 85;

if (score >= 90)
{
    printf("A\n");
}
else if (score >= 80)
{
    printf("B\n");
}
else if (score >= 70)
{
    printf("C\n");
}
else
{
    printf("F\n");
}
```

``` mermaid
flowchart TD
    A["score >= 90?"] -->|"Yes"| B["A"]
    A -->|"No"| C["score >= 80?"]
    C -->|"Yes"| D["B"]
    C -->|"No"| E["score >= 70?"]
    E -->|"Yes"| F["C"]
    E -->|"No"| G["F"]
```

> \[!IMPORTANT\] `if - else if - else`에서는 위에서부터 조건을 검사하며,
> 하나의 분기가 선택되면 나머지 분기는 실행하지 않는다.

------------------------------------------------------------------------

## 6.1 조건의 순서가 중요하다

다음 코드를 보자.

``` c
if (score >= 60)
{
    printf("Pass\n");
}
else if (score >= 90)
{
    printf("Excellent\n");
}
```

`score`가 `95`여도 첫 번째 조건 `score >= 60`이 먼저 참이므로
`Excellent` 분기에 도달하지 않는다.

의도에 따라 다음처럼 더 구체적인 조건을 먼저 검사할 수 있다.

``` c
if (score >= 90)
{
    printf("Excellent\n");
}
else if (score >= 60)
{
    printf("Pass\n");
}
```

> **조건문의 결과는 조건 자체뿐 아니라 검사 순서에도 영향을 받는다.**

------------------------------------------------------------------------

# 7. 중첩 조건문

`if` 내부에 또 다른 `if`를 작성할 수 있다.

``` c
if (age >= 20)
{
    if (has_license)
    {
        /* ... */
    }
}
```

``` mermaid
flowchart TD
    A["age >= 20?"] -->|"No"| D["종료"]
    A -->|"Yes"| B["has_license?"]
    B -->|"Yes"| C["조건 만족"]
    B -->|"No"| D
    C --> D
```

중첩이 너무 깊어지면 코드의 흐름을 이해하기 어려워질 수 있다.

``` text
if
 └─ if
     └─ if
         └─ if
```

복잡한 조건은 논리 연산자 또는 이후 배우는 함수로 분리하는 방법을
고려한다.

# 8. `switch`

하나의 값을 여러 경우와 비교할 때 `switch`를 사용할 수 있다.

기본 구조:

``` c
switch (expression)
{
case value1:
    /* ... */
    break;

case value2:
    /* ... */
    break;

default:
    /* ... */
    break;
}
```

예:

``` c
int command = 2;

switch (command)
{
case 1:
    printf("Start\n");
    break;

case 2:
    printf("Stop\n");
    break;

case 3:
    printf("Reset\n");
    break;

default:
    printf("Unknown\n");
    break;
}
```

``` mermaid
flowchart TD
    A["command"] --> B{"값"}
    B -->|"1"| C["Start"]
    B -->|"2"| D["Stop"]
    B -->|"3"| E["Reset"]
    B -->|"기타"| F["Unknown"]
```

------------------------------------------------------------------------

## 8.1 `break`

`switch`에서 `break`는 현재 `switch`를 빠져나오게 한다.

``` c
case 1:
    printf("Start\n");
    break;
```

`break`가 없다면 다음 `case`의 코드로 계속 진행하는 **fall-through**가
발생할 수 있다.

``` c
switch (value)
{
case 1:
    printf("A\n");

case 2:
    printf("B\n");
    break;
}
```

`value == 1`이면 `A` 이후 `B`까지 실행될 수 있다.

> \[!WARNING\] 의도하지 않은 `switch` fall-through는 버그가 되기 쉽다.
> 의도적인 fall-through인지 항상 확인한다.

------------------------------------------------------------------------

## 8.2 `default`

어떤 `case`에도 해당하지 않을 때 실행된다.

``` c
default:
    printf("Unknown command\n");
    break;
```

입력값이나 명령값을 처리할 때 예외적인 경우를 명시적으로 처리하는 데
유용하다.

------------------------------------------------------------------------

# 9. `if`와 `switch`

둘 다 분기를 만들지만 사용 목적이 조금 다르다.

  상황                   적합한 방식
  ---------------------- ---------------------------
  범위 비교              `if`
  복합 논리 조건         `if`
  특정 값 여러 개 비교   `switch`
  상태 코드 처리         `switch`가 유용할 수 있음

예:

``` c
if (temperature >= 80)
{
    /* 범위 조건 */
}
```

``` c
switch (state)
{
case 0:
    break;

case 1:
    break;

default:
    break;
}
```

임베디드에서는 상태 머신(FSM)을 구현할 때 `switch`를 자주 접하게 된다.

``` mermaid
flowchart LR
    A["State"] --> B["switch"]
    B --> C["IDLE"]
    B --> D["RUN"]
    B --> E["ERROR"]
```

# 10. 반복문

같은 작업을 여러 번 수행해야 할 때 반복문을 사용한다.

대표적인 반복문:

``` text
for
while
do while
```

``` mermaid
flowchart TD
    A["반복문"] --> B["for"]
    A --> C["while"]
    A --> D["do while"]

    B --> E["반복 횟수가 비교적 명확할 때"]
    C --> F["조건 중심 반복"]
    D --> G["최소 한 번 실행 후 조건 검사"]
```

# 11. `for`

반복 횟수나 인덱스 변화가 명확한 경우 자주 사용한다.

기본 구조:

``` c
for (초기화; 조건식; 증감식)
{
    /* 반복 코드 */
}
```

예:

``` c
for (int i = 0; i < 5; i++)
{
    printf("%d\n", i);
}
```

출력:

``` text
0
1
2
3
4
```

------------------------------------------------------------------------

## 11.1 `for` 실행 순서

``` c
for (int i = 0; i < 5; i++)
{
    printf("%d\n", i);
}
```

실행 흐름:

``` mermaid
flowchart TD
    A["int i = 0"] --> B{"i < 5?"}
    B -->|"Yes"| C["반복문 본문 실행"]
    C --> D["i++"]
    D --> B
    B -->|"No"| E["반복문 종료"]
```

순서를 반드시 기억한다.

``` text
1. 초기화
2. 조건 검사
3. 본문 실행
4. 증감
5. 조건 검사
6. 반복
```

------------------------------------------------------------------------

## 11.2 반복 횟수 추적

``` c
for (int i = 0; i < 3; i++)
{
    printf("%d\n", i);
}
```

  반복          `i` `i < 3`   실행
  ----------- ----- --------- ------
  1               0 true      실행
  2               1 true      실행
  3               2 true      실행
  종료 검사       3 false     종료

이런 표를 직접 작성하면 반복문을 이해하기 쉽다.

# 12. `while`

조건이 참인 동안 반복한다.

기본 구조:

``` c
while (condition)
{
    /* 반복 코드 */
}
```

예:

``` c
int count = 0;

while (count < 5)
{
    printf("%d\n", count);
    count++;
}
```

``` mermaid
flowchart TD
    A["count = 0"] --> B{"count < 5?"}
    B -->|"Yes"| C["count 출력"]
    C --> D["count++"]
    D --> B
    B -->|"No"| E["종료"]
```

------------------------------------------------------------------------

## 12.1 종료 조건을 반드시 생각한다

다음 코드는 문제가 있다.

``` c
int count = 0;

while (count < 5)
{
    printf("%d\n", count);
}
```

`count`가 변하지 않기 때문에 조건은 계속 참이다.

``` mermaid
flowchart TD
    A["count = 0"] --> B{"count < 5?"}
    B -->|"Yes"| C["출력"]
    C --> B
```

이런 반복을 **무한 루프(infinite loop)**라고 한다.

> \[!WARNING\] 반복문을 작성할 때는 항상 다음을 확인한다.
>
> 1.  반복 조건은 무엇인가?
> 2.  반복 중 어떤 값이 변하는가?
> 3.  언제 조건이 거짓이 되는가?

------------------------------------------------------------------------

# 13. `do-while`

`do-while`은 본문을 먼저 실행하고 그 뒤 조건을 검사한다.

``` c
do
{
    /* 반복 코드 */
}
while (condition);
```

예:

``` c
int count = 0;

do
{
    printf("%d\n", count);
    count++;
}
while (count < 5);
```

``` mermaid
flowchart TD
    A["본문 실행"] --> B{"조건 검사"}
    B -->|"Yes"| A
    B -->|"No"| C["종료"]
```

`while`과 가장 큰 차이는 **본문이 최소 한 번 실행된다는 것**이다.

------------------------------------------------------------------------

## 13.1 `while`과 `do-while` 비교

### `while`

``` c
while (condition)
{
    /* ... */
}
```

조건을 먼저 검사한다.

### `do-while`

``` c
do
{
    /* ... */
}
while (condition);
```

본문을 먼저 실행한다.

``` mermaid
flowchart LR
    A["while"] --> B["조건 먼저"]
    C["do-while"] --> D["본문 먼저"]
```

> \[!NOTE\] `do-while` 끝의 세미콜론 `;`을 빠뜨리지 않는다.

`continue`는 현재 반복의 남은 부분을 건너뛰고 다음 반복으로 진행한다.

``` c
for (int i = 0; i < 5; i++)

```

출력:

``` text

1

4
```

``` mermaid
flowchart TD

    B -->|"Yes"| C["continue"]
    C --> D["다음 반복"]

```

  ------------ -------------------------------------

# 16. 중첩 반복문

반복문 내부에 또 다른 반복문을 작성할 수 있다.

``` c
for (int i = 0; i < 3; i++)
{
    for (int j = 0; j < 2; j++)
    {
        printf("i=%d, j=%d\n", i, j);
    }
}
```

동작 횟수:

``` text
외부 반복: 3번
내부 반복: 외부 반복마다 2번

총 실행: 3 × 2 = 6번
```

``` mermaid
flowchart TD
    A["i 반복"] --> B["j 반복"]
    B --> C["본문 실행"]
    C --> B
    B -->|"j 종료"| A
```

중첩 반복문은 이후 다음 분야에서 많이 사용한다.

``` text
2차원 배열
행렬
완전 탐색
그래프
이미지 처리
프레임 버퍼
```

# 17. 반복문 선택 기준

처음에는 다음 기준으로 선택하면 된다.

  상황                             추천
  -------------------------------- ------------
  반복 횟수가 명확함               `for`
  특정 조건이 유지되는 동안 반복   `while`
  최소 한 번 실행해야 함           `do-while`

예:

``` c
for (int i = 0; i < 10; i++)
{
    /* 10회 반복 */
}
```

``` c
while (data_available)
{
    /* 데이터가 존재하는 동안 */
}
```

``` c
do
{
    /* 최소 한 번 실행 */
}
while (retry);
```

# 18. Off-by-One Error

반복문에서 매우 자주 발생하는 오류다.

다음 두 조건을 비교한다.

``` c
i < 10
```

``` c
i <= 10
```

`i = 0`에서 시작한다고 가정하면 반복 횟수가 다르다.

``` c
for (int i = 0; i < 10; i++)
{
    /* 0 ~ 9 */
}
```

총 10회 실행된다.

반면:

``` c
for (int i = 0; i <= 10; i++)
{
    /* 0 ~ 10 */
}
```

총 11회 실행된다.

``` mermaid
flowchart TD
    A["i = 0"] --> B["i < 10"]
    B --> C["0 ~ 9"]
    C --> D["10회"]

    E["i = 0"] --> F["i <= 10"]
    F --> G["0 ~ 10"]
    G --> H["11회"]
```

# 20. Short-Circuit와 제어 흐름

`&&`, `||`의 단락 평가는 제어 흐름에도 영향을 준다.

``` c
if (ptr != NULL && *ptr == 10)
{
    /* ... */
}
```

첫 번째 조건이 거짓이면 두 번째 조건을 평가하지 않는다.

``` mermaid
flowchart TD

    B -->|"No"| C["두 번째 조건 평가 안 함"]

```

현재는 포인터 문법보다 다음 원리를 기억한다.

> **조건식에서도 모든 표현식이 반드시 실행되는 것은 아니다.**

# 22. 임베디드와 제어 흐름

임베디드 프로그램에서는 제어 흐름이 하드웨어 상태와 직접 연결되는 경우가
많다.

예:

``` text
버튼이 눌렸는가?
센서 값이 임계값을 넘었는가?
UART 데이터가 도착했는가?
타이머가 만료되었는가?
현재 시스템 상태는 무엇인가?
```

개념적인 예:

``` c
if (temperature > LIMIT)
{
    /* cooling system on */
}
```

또는:

``` c
switch (state)
{
case STATE_IDLE:
    break;

case STATE_RUN:
    break;

case STATE_ERROR:
    break;

default:
    break;
}
```

이 구조는 이후 FSM(Finite State Machine)으로 발전한다.

``` mermaid
stateDiagram-v2
    [*] --> IDLE
    IDLE --> RUN : start
    RUN --> IDLE : stop
    RUN --> ERROR : fault
    ERROR --> IDLE : reset
```

# 23. 임베디드의 무한 루프

펌웨어에서는 의도적으로 프로그램을 계속 실행시키는 구조를 자주 사용한다.

개념적인 형태:

``` c
int main(void)
{
    /* initialization */

    while (1)
    {
        /* main loop */
    }
}
```

일반 프로그램에서 의도하지 않은 무한 루프는 버그지만, 임베디드의 main
loop 구조에서는 무한 반복이 의도된 설계일 수 있다.

``` mermaid
flowchart TD
    A["Power On"] --> B["Initialization"]
    B --> C["Main Loop"]
    C --> D["Input 확인"]
    D --> E["상태 처리"]
    E --> F["Output 갱신"]
    F --> C
```

> \[!IMPORTANT\] **무한 루프 자체가 항상 버그인 것은 아니다.**
>
> 중요한 것은 해당 반복이 의도된 설계인지 확인하는 것이다.

# 24. Polling과 제어 흐름

임베디드에서 특정 상태를 반복해서 확인하는 방식을 Polling이라고 한다.

개념적인 예:

``` c
while (1)
{
    if (button_pressed)
    {
        /* 버튼 처리 */
    }

    if (uart_data_ready)
    {
        /* UART 처리 */
    }
}
```

``` mermaid
flowchart TD
    A["Main Loop"] --> B{"Button?"}
    B -->|"Yes"| C["Button 처리"]
    B -->|"No"| D{"UART Data?"}
    C --> D
    D -->|"Yes"| E["UART 처리"]
    D -->|"No"| A
    E --> A
```

이후 Interrupt와 RTOS를 배우면 이런 구조와 비교하게 된다.

``` text
Polling
   ↓
Interrupt
   ↓
RTOS Task
```

현재는 `while`, `if`가 실제 펌웨어 제어 구조의 기반이라는 점을 이해한다.

# 25. 자주 하는 실수

## 25.1 `=`와 `==` 혼동

잘못된 의도:

``` c
if (number = 10)
{
    /* ... */
}
```

비교를 원했다면:

``` c
if (number == 10)
{
    /* ... */
}
```

------------------------------------------------------------------------

## 25.2 조건 순서 오류

``` c
if (score >= 60)
{
    printf("Pass\n");
}
else if (score >= 90)
{
    printf("Excellent\n");
}
```

더 구체적인 조건이 실행되지 않을 수 있다.

------------------------------------------------------------------------

## 25.3 무한 루프

``` c
int i = 0;

while (i < 10)
{
    printf("%d\n", i);
}
```

`i`가 변하지 않는다.

수정:

``` c
while (i < 10)
{
    printf("%d\n", i);
    i++;
}
```

------------------------------------------------------------------------

## 25.4 Off-by-One

``` c
for (int i = 0; i <= 10; i++)
```

와:

``` c
for (int i = 0; i < 10; i++)
```

의 반복 횟수가 다르다.

------------------------------------------------------------------------

## 25.5 `switch`의 `break` 누락

``` c
switch (command)
{
case 1:
    printf("Start\n");

case 2:
    printf("Stop\n");
    break;
}
```

의도하지 않은 fall-through가 발생할 수 있다.

------------------------------------------------------------------------

## 25.6 `break`와 `continue` 혼동

``` text
break
→ 반복문 종료

continue
→ 현재 반복만 건너뜀
```

------------------------------------------------------------------------

## 25.7 `do-while` 세미콜론 누락

``` c
do
{
    /* ... */
}
while (condition);
```

마지막 `;`에 주의한다.

# 32. 반복문을 볼 때 사용하는 사고 방식

반복문을 만나면 다음 순서로 분석한다.

``` mermaid
flowchart TD
    A["초기 상태는?"] --> B["반복 조건은?"]
    B --> C["본문에서 무엇을 하는가?"]
    C --> D["어떤 값이 변하는가?"]
    D --> E["언제 종료되는가?"]
    E --> F["총 몇 번 실행되는가?"]
```

이를 체크리스트로 만들면:

-   [ ] 초기값 확인
-   [ ] 조건식 확인
-   [ ] 본문 확인
-   [ ] 증감/상태 변화 확인

## 최종적으로 기억할 다섯 문장

> **1. 제어 흐름은 프로그램의 코드가 어떤 순서와 조건으로 실행되는지를
> 결정한다.**

> **2. 조건문은 비교·논리 연산으로 만든 조건식을 이용해 실행 경로를
> 선택한다.**

> **3. 반복문은 `초기 상태 → 조건 → 실행 → 상태 변화 → 종료`의 구조로
> 분석한다.**

> **4. 반복문에서는 무한 루프와 Off-by-One Error를 항상 확인한다.**

> **5. 임베디드에서는 `if → 상태 판단`, `switch → FSM`,
> `while → main loop`, `for → 데이터 처리`로 직접 연결된다.**
